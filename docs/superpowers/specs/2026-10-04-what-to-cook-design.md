# what-to-cook — дизайн

Дата: 2026-10-04

## Цель

Убрать паралич выбора «что приготовить на обед/ужин». Пользователь вводит
продукты, которые есть дома, и получает три варианта блюд с коротким рецептом.

Успех: от открытия страницы до списка блюд — одно поле и одна кнопка;
пользоваться можно с телефона на кухне; всё бесплатно.

## Ограничения

- Бесплатно: и LLM, и хостинг.
- Один пользователь, без аккаунтов и логина.
- Без сервера: статическая страница, запрос к LLM идёт из браузера.
- Без сборщика и без npm-зависимостей: нативные ES-модули.
- Интерфейс и ответы модели — на русском.

## Экран

Одна страница, вёрстка под телефон (работает и на десктопе).

1. Поле «Что есть дома» — многострочный свободный текст.
   Значение сохраняется в `localStorage` и подставляется при следующем визите.
2. Переключатель приёма пищи: «обед» / «ужин». По умолчанию «ужин».
3. Кнопка «Что приготовить?». Пока идёт запрос — заблокирована, показывает
   индикатор загрузки. При пустом поле продуктов запрос не отправляется,
   под полем выводится подсказка «Напиши, что есть дома».
4. Результат — три компактные карточки. В карточке только главное:
   название блюда, время готовки в минутах и пометка «всё есть дома» либо
   «докупить: N» (N — число недостающих продуктов).
   Нажатие на карточку открывает попап с деталями:
   - название и время;
   - какие продукты пользователя используются;
   - чего не хватает (если список пуст — блок не выводится);
   - шаги приготовления, 4–6 коротких строк.
   Попап закрывается крестиком, клавишей Esc или нажатием мимо него.
5. Кнопка «Ещё варианты» — появляется после первого результата. Отправляет
   новый запрос с теми же продуктами и списком уже показанных названий как
   исключений. Три новые карточки добавляются ниже уже показанных. Список
   карточек и исключений копится, пока не изменён текст продуктов или приём
   пищи; после изменения следующий запрос начинает список заново.
   Индикатор загрузки и сообщения об ошибках выводятся под карточками.
6. Кнопка-шестерёнка открывает настройки: поле для API-ключа, ссылка на
   страницу получения ключа (Google AI Studio), кнопка «Сохранить».
   Если ключа в `localStorage` нет, настройки открываются сами при загрузке
   страницы.

## Модули

| Файл | Ответственность | Зависит от |
|---|---|---|
| `index.html` | разметка | — |
| `style.css` | оформление | — |
| `prompt.js` | `buildPrompt({products, meal, exclude})` → строка промпта. Чистая функция | — |
| `llm.js` | `suggestDishes({apiKey, prompt})` → `Promise<Dish[]>`; `parseDishes(json)`; `toUserError(err)` | `fetch` |
| `storage.js` | чтение/запись ключа и списка продуктов | `localStorage` |
| `app.js` | события, состояние экрана, рендер карточек | все выше |

`Dish`:

```
{
  name: string,
  minutes: number,
  uses: string[],
  missing: string[],
  steps: string[]
}
```

## LLM

- Провайдер: Google Gemini, бесплатный тариф, REST-эндпоинт `generateContent`,
  вызов из браузера через `fetch`.
- Модели — константы в `llm.js`: основная `gemini-flash-latest`, запасная
  `gemini-flash-lite-latest`. При HTTP 503, 404 или 429 от основной — один
  повтор на запасной (квоты у моделей раздельные; у основной на бесплатном
  тарифе 20 запросов в сутки).
- Ответ запрашивается структурированным: `responseMimeType: application/json`
  плюс `responseSchema` — массив из трёх `Dish`.
- Промпт требует: ровно три блюда; строить в первую очередь на имеющихся
  продуктах; базовые вещи (соль, перец, масло, вода) считать имеющимися;
  недостающего — минимум; блюдо уместно для выбранного приёма пищи;
  не предлагать блюда из списка исключений; отвечать на русском.

## Поток данных

```
клик → app.js читает поле и переключатель
     → storage.js сохраняет продукты
     → prompt.js собирает промпт
     → llm.js: fetch → Gemini → JSON → parseDishes → Dish[]
     → app.js рендерит карточки, добавляет названия в exclude
```

## Ошибки

`toUserError` превращает сбой в текст, который показывается на странице.
Если продукты и приём пищи не менялись с прошлого запроса, уже показанные
карточки остаются на экране, сообщение выводится под ними; иначе карточек
на экране нет и выводится только сообщение. Поле продуктов и кнопка остаются доступными.

Запрос прерывается по таймауту через 45 секунд и считается сбоем сети.

Если `localStorage` недоступен, ключ и продукты хранятся в памяти страницы
до перезагрузки.

| Ситуация | Сообщение | Действие |
|---|---|---|
| ключа нет | — | открыть настройки |
| HTTP 400 с `error.status = FAILED_PRECONDITION` (блокировка по региону) | «Gemini недоступен из твоего региона. Включи VPN и попробуй ещё раз.» | — |
| HTTP 400/401/403 | «Ключ не подошёл. Проверь его в настройках.» | открыть настройки |
| HTTP 429 (от обеих моделей) | «Лимит бесплатных запросов исчерпан. Попробуй позже.» | — |
| HTTP 5xx | «Gemini сейчас недоступен. Попробуй позже.» | — |
| сбой сети / `fetch` бросил исключение | «Не достучался до Gemini. Проверь интернет; возможно, нужен VPN.» | — |
| ответ не JSON или не проходит проверку формы | «Не понял ответ модели. Нажми ещё раз.» | — |

`parseDishes` проверяет форму: массив, у каждого элемента непустые `name` и
`steps`. Отсутствующие `uses`/`missing` считаются пустыми списками,
отсутствующее `minutes` — блок времени не выводится. Пустой массив — ошибка
формы.

## Безопасность

- API-ключ хранится только в `localStorage` браузера пользователя, в
  репозиторий и в код не попадает.
- Текст от модели вставляется в DOM через `textContent`, не через `innerHTML`.

## Тесты

`node --test`, без фреймворков и зависимостей.

- `prompt.js`: в промпт попадают продукты, приём пищи, исключения; при пустом
  списке исключений блок исключений не добавляется.
- `llm.js` / `parseDishes`: валидный ответ; пустой массив; не-JSON; элемент
  без `name`; элемент без `uses`/`missing`.
- `llm.js` / `toUserError`: 401, 429, 500, сетевое исключение.
- `suggestDishes` тестируется с подменённым `fetch`.

UI проверяется вручную в браузере: первый запуск без ключа, успешный запрос,
«Ещё варианты», неверный ключ, отключённая сеть.
